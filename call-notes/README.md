# 通话跟进 · 浏览器本地版

基于 Mac 客户端 0.8.5，部署为 GitHub Pages 静态页面；不需要新增云端数据库或 OSS。

## 使用

1. 打开 `/app-hub/call-notes/`，使用普通浏览窗口。
2. 在连接与设置中输入百炼密钥。默认北京地域 Base URL、`qwen-audio-3.1-asr-flash` 转写及 `qwen-plus` 总结；设置保存后可点“使用右侧已保存的百炼账户”共用密钥。
3. 导入文件名为 `号码或称呼_YYYYMMDD_HHMMSS.m4a` 等格式的录音。号码用于精确查询已有飞书客户。文件名没有号码时可手动关联。
4. 勾选录音进行分析；检查草稿、关联客户、确认姓名建议后，勾选并保存到飞书。分析本身不会写入飞书。
5. 定期导出备份，并确认下载文件已保存。恢复备份只合并本地不存在的记录，不覆盖本地相同录音的记录。

## 数据保存位置

- 录音副本、队列、转写和草稿：当前浏览器的 IndexedDB（`grace-call-notes-v1`）。
- 原始录音：仍保留在用户电脑原文件夹。网页没有权限删除原始文件。
- API 密钥：仅当前页面内存。刷新或关闭后需重新输入；不写入数据库、备份或源码。
- 备份：JSON，包含转写、草稿、处理状态，不含录音和密钥。恢复后要分析录音，请重新导入同一份原始文件；按 SHA-256 重新关联，不会生成重复条目。
- 已保存的跟进：飞书。清除网站数据不会删除飞书记录。

没有将录音或进度上传云端长期保存；分析时录音和文字仍发送至配置的 AI 服务，客户查询和确认保存使用现有飞书云函数。

## 限制与保护

- 浏览器关闭后不再继续处理；重开保留已完成的分段转写，未完成项可重试。写入中断转为“需确认结果”，先核对飞书再恢复。
- WAV 直接转换为 16kHz 单声道 PCM；其他格式由 Web Audio 解码，M4A 支持取决于实际编码及浏览器。单个输入文件上限 512 MB，大文件解码受电脑内存影响。
- 百炼分段 210 秒、重叠 2 秒；成功分段持久保存，重试不会重复请求已成功段。
- 需要支持 IndexedDB、Web Crypto、Web Locks 和 Web Audio 的现代浏览器。Web Locks 避免同一浏览器多个标签页同时处理；不能防止其他设备或 Mac App 同时编辑客户。
- 存储不足会停止操作，不能悄悄继续写飞书。浏览器主动清理、用户清除网站数据或删除浏览器配置可删除本地数据；“保护本地存储”不能阻止用户手动清除。
- 历史通话只追加日志，不回退更新的意向和跟进安排；保存前重读客户数据，已有姓名不覆盖。现有云函数不提供原子追加，仍需避免跨应用并发保存同一客户。
- 部署不含客户数据和密钥。此仓库以及网页源码公开。GitHub Pages 同一域名下其他网页与本页共享浏览器同源权限，应只在可信设备和浏览器中使用。

## 验证

迁移时已检查现有飞书及百炼接口对 GitHub Pages Origin 的 CORS 预检支持。离线领域测试及隔离 Chrome 流程测试使用模拟接口；未调用收费 AI 或真实写入飞书。实际录音编码、百炼账号模型权限及真实写回仍需用户用一条录音验证。
